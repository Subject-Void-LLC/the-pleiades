# The Pleiades 0.3.0 "Paranoid Porpoise"

The first tagged release. The Pleiades is a strongly typed automation mesh: you describe
devices in an inventory, write runbooks that call typed methods on them, check a runbook
before it runs, run it over real SSH, WinRM, Telnet or a device's API, and undo it later
from its journal. It also converts Ansible playbooks into runbooks.

This is a pre-1.0 release. Read [Start here](../01-start-here.md) for what is built and
proven and what is not before relying on any part of it.

## What you can do with it

- **Run it as one binary, with no server.** `pleiades` reads a static inventory and a
  credential file, validates a runbook before anything runs (`pleiades validate`), runs it
  (`pleiades run`), or calls one method with no runbook (`pleiades adhoc`). Every run is
  journaled, and `pleiades rollback <run-id>` undoes it from the journal.
- **Or run it as a Controller and Runners.** `controller` serves an API with
  authentication, role-based access, a scheduler and an audit trail; `runner` pulls jobs
  over NATS JetStream and runs them with the same engine as the CLI.
- **Write runbooks a person or an agent can read.** Variables at the runbook, block and
  task level, `set_fact`, `group_vars` and `host_vars`; `loop:`; `until:` with `retries:`
  and `delay:`; `changed_when:`, `failed_when:`, `ignore_errors:`, `assert` and `fail`;
  `block`, `rescue` and `always`. Each loop item and each try is its own journal entry, so a
  rollback undoes them one by one. See [Writing runbooks](../04-writing-runbooks.md).
- **Check before you change.** `pleiades run --mode check` predicts what each task would do
  for most methods and names every task it could not check.
- **Reach many kinds of device.** 210 methods in the module catalog, 208 implemented, across
  Linux hosts (and the file methods on FreeBSD and macOS), Windows over WinRM, Cisco IOS XE, FRR and Open vSwitch, NETCONF and
  HTTP devices, containers, VirtualBox and VMware Fusion VMs, Cisco Modeling Labs, and Batfish
  for checking a network change before it is made. The
  [module reference](../reference/modules/index.md) lists each one, generated from the code.
- **Move from Ansible.** `pleiades forge migrate-playbook` converts a playbook and says what
  it could not convert and why. See [Migrating from Ansible](../03-migrating-from-ansible.md).

## Install

Download the archive for your system and `SHA256SUMS` from the release page, check the
archive, and unpack it on your `PATH`. Archives are built for Linux, macOS and Windows, on
amd64 and arm64. Each holds `pleiades`, `controller` and `runner`. The steps are in
[Get started](../02-get-started.md).

## Patch releases

A 0.3.x patch release never breaks a runbook that runs on 0.3.0, and it may add: a method, a
parameter, a runbook keyword or more of the template language. See
[Releases and stability](../13-releases-and-stability.md).

## Known limits

- The archives are **not signed**, and there is no SBOM or build provenance yet. Check each
  download against `SHA256SUMS`.
- On the Controller and Runner, a device's credential travels on the dispatch message and
  can stay in the JetStream stream for its retention window. Removing credentials from the
  bus is the next release's work.
- Not built: handlers (`notify:`), `serial:`, `async`/`poll`, and `with_*` forms other than
  `with_items`. A variable's winner follows scope (the narrower scope wins), which is not
  Ansible's order.
- Templates are a bounded subset of Jinja: `if`, `for`, `set`, comparisons, `and`/`or`/`in`,
  the `is` tests and literals work; arithmetic, inline `if`, computed subscripts, macros and
  includes are refused by name. `pleiades doc filters` lists exactly what is supported.
- External Collections load only on Linux, where Landlock confines them.
- The web UI under `web/` is a mockup. The views the Controller serves itself are real.
- `net.junos.config` and `net.eos.config` are declared and not implemented.
