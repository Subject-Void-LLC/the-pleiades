A credential file holding SNMP fields does not survive an older build: it ignores them, so a device holding SNMP fields alone reads as an empty login rather than as no credential, and the first credential it saves rewrites the file without any device's SNMP fields or short-community mark. An older Runner given a template's `pleiades_snmp` credential masks the SNMPv3 user and protocol names by value, scrubbing words such as `sha256` from the job log, and a short community too, without the warning; releases before 1.0 move forward only, so keep a copy of `.pleiades/credentials.yaml` before running an older build against it.
