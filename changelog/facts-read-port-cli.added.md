A `pleiades run`, a check included, can now read the devices' stored facts: the executor reads the project's `.pleiades/facts` through the engine's fact read port, creating nothing, and a store that is there but cannot be read is an error rather than a device with no facts. Nothing in a run asks for a stored fact yet (the `facts` template root is Phase 41e's), and a Runner has no reads until the Controller puts them on the dispatch.
