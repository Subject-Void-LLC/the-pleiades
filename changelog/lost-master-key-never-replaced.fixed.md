A project whose master key was lost no longer gets a new one from `add-credential`, `add-secret`, `add-registry-credential`, `add-database-connection`, `seal-key`, an import, or a run that reads a credential or stores a fact, while it holds credentials, named secrets, a seal key or stored facts sealed under the old key: each refuses, naming what it found and the key to restore (`.pleiades/master.key` or `PLEIADES_MASTER_KEY`), and says to remove the files you accept losing if the key is truly gone. A new project still gets its key from its first command.
