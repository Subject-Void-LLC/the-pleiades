A Windows server now has `CommandExecCapable`, through `WindowsShellCapable`, because it can run a command outside any shell over WinRM. SSH-only methods that require it, such as `exec.command`, are still refused for a Windows server, now by the transport check. The generic `svc.*` methods now list `ssh` and `winrm` as their transports and `pkg.*` lists `ssh`, and each refuses a device that cannot reach the concrete method it resolves to.
