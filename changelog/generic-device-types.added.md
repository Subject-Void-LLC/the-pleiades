Four generic device types manage a device nobody has written a type for, by the protocol it speaks: `generic_ssh`, `generic_netconf`, `generic_http` and `generic_grpc`. Beyond a small baseline, a generic device's capabilities come from the device itself: `pleiades onboard <name>` (or `POST /api/v1/inventory/devices/{name}/onboard`, which needs the new `inventory:onboard` scope) probes it over its protocol with its stored credential and records what the device's answers prove, as a revision in its history. A generic device starts `discovered`, which runs nothing, and becomes `active` when onboarding succeeds. The property onboarding writes, `discovered`, is refused on every other write path: `add-host --set`, a hand-written `hosts.yaml` and a sync plugin each fail naming it, so an inventory that already used a property of that name must rename it.
