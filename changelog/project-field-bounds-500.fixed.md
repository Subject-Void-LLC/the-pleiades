Creating or updating a project through the API with a `name` over 253 bytes, a `description` over 1024, an `scm_url` over 2048 or an `scm_branch` over 255 is now refused with a 400 that names the field and its bound, where it used to answer 500 "internal error". The bound is in bytes, measured after trimming, as the database measures it; the web UI's project form already refused such a value with an error beside the field, and now reads the same bounds.
