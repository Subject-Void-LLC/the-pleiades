Fixed a task `timeout:` that never ended a command over SSH when the command left a child holding its output: OpenSSH's sshd answers the client's close only once that output ends, and on Debian's sshd the signal never reached the command, so a `sleep 60 &` ran its whole minute past a three-second timeout and was reported a success. The task now fails within two seconds of its timeout. The command itself may still run on such a device; `async:` stops it.
