A task's `when`, `when_or` and `when_cel` can read the stored facts of the device it runs on with `pleiades run`, by a key written in the runbook (`facts["os.family"] == "debian"`), with what the run's own earlier tasks gathered on top. A key with no answer is unknown, and a condition is three-valued: a result decided without the key stands, and the task fails, naming the keys and the methods that gather them, only when the result itself is unknown, which `is defined`, `default()` and `has()` cannot hide. A key reads absent only where a built-in method claims that its silence proves it (`absent_when_not_emitted`), which none does yet, so a family's item such as `package.nginx` is tested through the gather's registered result. A check reports a task unchecked (exit 3) when its result depends on a fact an earlier checked task would change. A fact never reaches a parameter or any output, and on the Walk tier a runbook reading one is refused at launch, check and relaunch (a 422), at a schedule's write, and before any device is contacted.
