A Runner's facts and journal batches are now published on a subject that names it, and the broker lets a Runner publish only under the name its own credential carries. A Runner can no longer write another Runner's facts or journal, and a batch whose subject names a different Runner than its label is dropped. The subjects are `pleiades.jobs.facts.<runner>.<job>` and `pleiades.jobs.journal.<runner>.<job>` (they were `<job>` alone), so this changes the wire format: a Runner from before this release publishes to subjects the new broker refuses, and a Controller from before it cannot read the new subjects.

Runner credentials now come from a scoped signing key on the mesh account (role `runner`, whose publish permission the broker limits to that Runner's own facts and journal subjects). `controller mesh issue` mints under that scope, and its `--label` is the Runner's name: it must be one subject token (no dots, wildcards, spaces or slashes), unique per Runner, and it defaults to a generated `runner-<hex>` rather than the old shared `runner`.

Upgrading: an account minted before this release has no runner scope, so `controller mesh issue` refuses it by name. Run `controller mesh init` into a new directory (the old key is retired and its credentials stop working), then re-issue a credential for each Runner with `controller mesh issue --label <name>` and point each Runner at its own credential. A Runner now takes its name from its credential; without one it falls back to its host name and the broker enforces nothing.

A Runner whose host name cannot be read and that has no credential now stops at startup, since it would publish facts no batch can be checked for.
