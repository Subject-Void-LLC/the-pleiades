Stopping a task run with `async:` (a detached SSH command) is safer and says what happened. The stop now signals only the job's own process group, and only when the job's recorded process ID is a plain number above 1 in a job directory the account owns; a damaged or planted ID file could otherwise have made the stop signal every process the account may signal. Its errors now say whether the job was stopped, had already finished, or may still be running, so a finished job is not reported as stopped. A detached command that reached the device cut short is never started, startup output from the login (such as `~/.ssh/rc`) no longer breaks the job's polls, a device whose shell cannot give the job a process group runs the command attached instead, and a finished job whose output could not be read no longer leaves its directory, which holds the command, on the device. An SSH command whose output a method reads as it runs, and whose task is cancelled, now stops and fails with the cancellation, a command cut off for too much output is ended rather than waited on, and a command the SSH server refuses to start no longer has its whole text, which may hold a secret, in the error. Logs now mask a known secret inside any value, not only inside strings (an error, bytes, a URL, a struct), and mask fields and map keys named for a secret, such as `password`, and the members of a group named for one.
