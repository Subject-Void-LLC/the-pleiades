A stored fact now names the Collection its method came from (`by.collection` and `last_by.collection`: a built-in's first-party group, the version of The Pleiades that ran it and a digest of the group's method declarations, or an external program's file name and a digest of what it described), the same identity the run journal records for the task, on the command line and on the Controller. It names none for a method in no first-party group, a program whose file name cannot be recorded faithfully, a batch from a Runner before this release, or an identity the Controller clears. A value stored before it has none and its chain hash is unchanged, so a device's existing history still verifies. The command line's fact store refuses to store an identity its own build would not write for the method. The Controller holds a Runner's to a fixed check that reads no Unicode table (its shape, and a group holding no direction control, invisible or private-use character or line separator): a batch naming one that fails is stored with its facts and no identity, with a warning, and one the Controller's own toolchain would not make, or its own build would route to another group (a group added or a method moved between the two builds), is stored as sent and logged at info level. Reading returns each identity as it was stored: an edited one is found by the device's fact chain, and one that a later release's list of first-party groups would refuse still reads and verifies. A build from before this change reads a value stored with an identity without it, so its fact chain check reports that value as a break; no release before this one keeps facts, so this affects only development builds, and a set of Controllers sharing one database should run one build.
