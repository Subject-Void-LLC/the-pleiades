A gNMI, RESTCONF, `http.request` or `generic_http` onboarding device whose server requires a client certificate, and is presented none or one it does not accept, now fails as a refusal naming `tls_client_certificate` and saying the server processed no request, rather than as a server that is down; `wait.gnmi` and `wait.restconf` stop at once instead of trying until their timeout. When a reset hides the alert, one more connection that carries no request reads it. The CML, Kubernetes, container engine, Batfish and AI provider clients do not do this yet.
