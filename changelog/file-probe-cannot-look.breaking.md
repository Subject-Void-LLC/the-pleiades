A method that looks at a path on a device now fails, saying it cannot look, when the path is under a directory its login may not search, where it used to answer that the path was absent whether or not anything was there. The read-only methods whose answer changes are `file.stat` (it used to answer `exists: false`), `wait.path` (a wait for `state: absent` used to pass at once, and one for `present` waited out its timeout), `wait.search` (the file counted as missing), `scan.secrets` and `scan.vuln` (their target path), and `container.registry.info` reading a login file over SSH (it used to read as no logins). A method that changes a path (the `file.*`, `fs.*` and `archive.*` methods, `net.frr.config`, `build.digests.refresh`, `scan.sbom`, `db.pg.dump`, `db.pg.restore`, `db.pg.migrate`, and `container.registry.login`, `container.registry.logout`, `container.image.load`, `container.image.import` and `container.image.save` over SSH) now fails there at its first read, in a run and in a check, where it used to act, or predict, as if nothing were there. A runbook that branched on `exists == false` for such a path, or on a wait for it to be absent, now fails with "cannot look"; run the task as an account that may search the directory (`become`) to get the answer.
