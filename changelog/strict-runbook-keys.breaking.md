A runbook is now refused when it carries a key the runbook format does not have anywhere in the document, not only at the top level: an unknown key under `metadata:` or `secret_mask:`, a JSON key in the wrong case, or a repeated JSON key. Each refusal names the key, where it sits and, in YAML, its line. An Ansible keyword on a task (`loop:`, `become:`, `notify:` and the rest) is refused as one, pointing at the migration guide, and a lone undotted key that is not a task key or an engine action is refused instead of being read as a module name. A runbook that relied on such a key being ignored must drop it; in particular the `metadata.mcp*` keys, which nothing ever read, are no longer accepted.
