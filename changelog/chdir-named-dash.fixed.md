`exec.command` and `exec.shell` now run in the relative `chdir` they are given. With `chdir: "-"`, where `/bin/sh` is dash or BusyBox (Debian, Ubuntu, Alpine), they used to run in the login's home directory, or in `$OLDPWD` when the device set one, and report success; where it is bash they failed. With `CDPATH` set in the device's login environment, any other relative `chdir` could run under a `CDPATH` entry instead. Both come from `cd`, which reads `-` as the previous directory and searches `CDPATH` for a relative name even after `--`. Their `creates` and `removes` guards, `file.remove`'s check of a relative directory, `identity.user`'s home comparison and `gate.run`'s check directories are fixed the same way.
