A credential holding a value, an external reference or an input source for an input its managed type no longer declares, which an older release's reconcile leaves in place while a deployment runs it, could not be updated or used: every `PATCH /credentials/{id}`, rotating a compromised token included, was refused naming that input, and every job binding it failed at injection. An update now carries those as they are, unchecked and never shown: `GET /credentials/{id}` leaves out such a reference and `GET /credentials/{id}/input-sources` such a source, a write replacing the input sources keeps it, a dispatch leaves them out of the run, the binding rule judges the credential as the run does, and a value or a new reference sent for such an input is still refused. An update of a credential whose stored values this Controller cannot decrypt is refused with 409 instead of 400.
