`pleiades run --limit` (and a `serial:` batch) now checks each task before contact against every device its target names, as `pleiades validate`, which takes no limit, does: it refuses what validate refuses, such as a transport action naming a device outside the limit that lacks its capability, and it no longer refuses a template reading a variable that only a device outside the limit brings, such as a hub's `host_vars` value inside an `{% if %}` only the hub takes. The plan's blast radius still counts only the devices the run reaches.
