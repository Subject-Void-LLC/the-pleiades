Every first-party namespace is now reserved for The Pleiades whether or not a build includes that Collection: an external Collection can no longer use `kubernetes`, the namespace of a built-in fact family (`os`, `host`, `hardware`, `network`, `package`, `service`, `service_state`, `port`, `user`, `group`, `catalyst`), or a Collection's namespace in a build without it, for a method or a capability; nor declare a fact under any first-party namespace (`net.`, `container.`, `edge.` and the rest), where before only a fact a built-in declared was refused. An installed program doing any of these is refused when Collections are loaded, and loading stops there, so the other programs in its directory (and a Runner using that directory) do not load until it moves to a namespace of its own. The Controller now holds a batch's facts to the same floor. `pleiades validate` names the first-party Collection that holds a method a build does not include, and the lists ship as `docs/reference/schemas/first-party.json`, growing only on a minor release.
