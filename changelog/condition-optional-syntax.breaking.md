`validate` now reads conditions that use CEL's optional syntax, which it used to skip whole, so a runbook it passed may be refused: a register no task writes or a variable no scope sets read beside an optional read (`vars.?x.orValue(true) && result.probe.ok` after a rescued block that alone writes `probe`), `error.?` outside a rescue, a real task reading a checked task's result through `.?`, and a `.value()` of an optional read of a register or variable that may be missing. A task with `lock_acquisition: all_at_plan_time` whose condition reads `device`, or variables that differ by device (a `set_fact` in the runbook, or variables its devices bring), through the optional syntax used to run and is now refused when it runs, and `validate` now refuses `all_at_plan_time` on any task whose variables differ by device, plainly read or not, as the run already did.
