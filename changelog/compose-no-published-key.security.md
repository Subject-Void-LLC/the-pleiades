`docker-compose.yml` no longer carries a working `MASTER_ENCRYPTION_KEY` and `JWT_SECRET`. Every earlier copy of the file published the same key, so any compose stack started from one stored its credentials under a key anyone can read. `make up` now generates both with `controller setup` and writes them to `.env`. A stack whose database was encrypted under the published key is refused by setup, which names that key and both ways out, rather than given a new key that would leave that data unreadable.
