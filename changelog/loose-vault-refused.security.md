A `master.key`, `credentials.yaml` or `seal.key` that group or others can read or write, or that another user owns, is now refused before any secret is read, naming the file and the `chmod 600` or `chown` that fixes it, as OpenSSH refuses a loose private key. This is a behavior change: a project whose vault files were loosened by hand (or sit on a filesystem without POSIX modes, such as a Windows drive under WSL) stops working until they are fixed; the CLI, the Runner and the Controller's `CONTROLLER_CREDENTIALS_DIR` are all affected. Windows checks nothing, since POSIX modes do not apply there.
