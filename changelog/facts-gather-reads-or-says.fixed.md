`facts.gather` no longer records a package, service, port or account list it could not read as an empty one, which made every item look removed until the next run: a source whose listing fails fails the task, and a subset the task names that no source on the device answers fails it too, while one reached through `all` is a warning (so a converted `service_facts` now warns on a host with no service manager it reads, such as one run by SysV init, where Ansible skips). A Windows host without the account or TCP/IP cmdlets says so rather than reporting none, `rpm` counts as a package source only where its database exists, and a failed macOS `pkgutil` lookup fails the task. Services read as they are: systemd only where it booted, an OpenRC supervised service's state without its uptime, a FreeBSD daemon a non-root login cannot see as unknown rather than stopped, OpenRC's runlevels where `POSIXLY_CORRECT` is set, and on macOS a disabled daemon that is still installed is reported (stopped and disabled) with a status of `enabled` or `disabled` rather than its last exit status. `filter` matches the key a fact is stored under (so `package.glibc:*` finds a package two databases list), reads `[!x]`, `[^x]` and a backslash as Ansible's fnmatch does, and refuses a family name alone such as `package`; `gather_subset` gives the same answer in any order, as Ansible does; two item names differing only in a byte that is not UTF-8 keep separate keys; and a fact history reads a value repeated in a row as one value. The `filter` pattern changes apply to every build; the rest affect only builds after 0.3.0.
