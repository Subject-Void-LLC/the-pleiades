Added `serial:`: a runbook runs over its hosts a batch at a time (a number, a percentage, or a list of them, as in Ansible), in device-name order, a percentage counting the hosts whose lifecycle admits the run on both tiers, each batch finishing before the next starts and a failed batch stopping the rollout. On the CLI the batches are one run that `pleiades rollback` undoes whole; on a Controller each batch's devices are dispatched together (bounded by `forks` when set) once the previous batch has reported. A launch with credential inputs asked for at launch cannot run a runbook with `serial:`.
