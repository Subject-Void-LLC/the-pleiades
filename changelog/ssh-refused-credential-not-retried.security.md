A password or key the SSH server refuses is no longer tried again inside the same task. The dial retry sent the same refused credential three times, so one task with a wrong password counted as three failed logins: enough to lock the account on a host using `pam_faillock` at `deny=3`, and enough for OpenSSH 9.8 or later to block the Runner's address from that host for every job through its default `PerSourcePenalties`. A refused credential also no longer counts toward the circuit breaker, so a wrong password on one task cannot make another task to the same device fail with "circuit open".
