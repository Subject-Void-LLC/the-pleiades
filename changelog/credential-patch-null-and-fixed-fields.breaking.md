`PATCH /credentials/{id}` and `PATCH /credential-types/{id}` refuse a null on any field with a 400 that names it, and `PATCH /credentials/{id}` also refuses a null value inside `inputs` or `external`; leave a field out to keep it, or send an empty value to clear it. A null used to be read as an empty value: inside `inputs` it cleared a stored optional secret with a 200, a null `external` erased every reference, a null type `inputs` or `injectors` was read as an empty document, a null `name` answered 500 on a credential and 400 on a type, and a null on a fixed field was ignored. They also refuse a value that differs from the stored one for a field no update can change, with a 400 naming the field, where it used to be accepted and ignored with a 200: a credential's `credential_type` and `organization`, and a credential type's `namespace` and `organization`; sending the stored value is still accepted.
