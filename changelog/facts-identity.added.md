`facts.gather` now records four identity facts on Linux, FreeBSD, macOS and Windows: `os.machine_id`, `hardware.system_uuid`, `hardware.serial` and `hardware.virtualization` (`physical`, `vm:<hypervisor>`, `cloud:<provider>` or `container:<engine>`). Firmware placeholders such as "To be filled by O.E.M." are never stored. On Linux the UUID and serial, which only root may read, are simply absent for a login without root; FreeBSD, macOS and Windows give them to any login. The machine id is `/etc/machine-id` on Linux and FreeBSD and the install's `MachineGuid` on Windows, in the same 32-digit shape; macOS has none and reports none. The UUID is lowercase on every system. Inside a container (WSL included) or a FreeBSD jail the machine id, UUID and serial are not recorded at all: a container sees its host's values and its image's machine id, so every container of one image would otherwise read as one machine. A jail reads as `container:jail`. A hypervisor has the same name on every system, systemd-detect-virt's (`oracle` is VirtualBox, `microsoft` is Hyper-V, `other` is one the system does not name). Azure and Hyper-V both read as `vm:microsoft`, since the system cannot tell them apart, and only Linux tells a cloud instance from a virtual machine. On firmware older than SMBIOS 2.6, VirtualBox's among them, Windows reads the UUID's first three parts byte-swapped from how Linux and FreeBSD read them, so one virtual machine can report two UUIDs.
