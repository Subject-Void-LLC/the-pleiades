A secret read from an external source could reach a run unmasked. A credential's `external` reference, or an input source bound to an external-kind credential such as a HashiCorp Vault one, could name an input its type does not mark secret, and the value it resolved to filled that input, which the masking of a run's output does not cover. Both are now refused when the credential is written (`POST /credentials`, `PATCH /credentials/{id}`, `PUT /credentials/{id}/input-sources` and the web UI's form), and a reference stored before this is refused when a job dispatches, naming the credential and the input, without fetching the secret.
