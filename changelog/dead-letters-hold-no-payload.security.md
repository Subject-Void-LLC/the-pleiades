A dead letter now holds only the identifiers of the message it replaces (its subject, the event's id, type, correlation id, idempotency key and actor), never the message itself, and its reason is masked. A dispatch carries its credential, fields, extra variables and injected values, so every dead-lettered dispatch used to put a second copy of those secrets on the stream for the same retention. Dead letters written before this change still hold payloads until retention removes them; to remove them now, run `nats stream purge PLEIADES --subject 'pleiades.dlq.>'` against the deployment's broker.
