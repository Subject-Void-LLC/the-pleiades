A rollback now holds each recorded undo to the Collection declarations it was recorded under. An undo whose declaration's digest differs from this build's is refused, naming both versions and both digests, until `pleiades rollback --allow-skew <node>` (repeatable) or the API's `allow_skew` list accepts it by node, and a step so accepted carries `skew_accepted`. What a plan wants read without refusing (a skew accepted and the digests it accepted, a Collection whose documentation alone changed, a method moved to another group, an entry recorded with no Collection identity) is printed by `pleiades rollback`, listed under `rollback.warnings` in its `--json` report, and returned in `POST /jobs/{id}/rollback`'s `202` answer as `warnings`; a Runner puts each step it runs under an accepted skew in the job's log as a `task.warning`. Whatever is named, a recorded value of another type than the parameter takes or outside its declared choices, and a parameter the undo's method requires that the run did not record (unless the undo's digest is this build's), are refused with `--leave` as the only answer, in journals from before 0.4.0 too. The CLI refuses `--allow-skew` naming a node with no skew or one also named to `--leave`; both tiers refuse a name for a node the run did not change. The Controller marks a named node accepted even where its own declarations match, since the Runner compares its own, and a Runner refuses a step recorded under other declarations than its own unless the plan accepted it. The flag is advisory until Collection identities are signed, since the digests are public. Every Collection group, version and digest a refusal or warning prints is quoted.
