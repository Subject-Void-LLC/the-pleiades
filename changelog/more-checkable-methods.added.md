69 of the 78 implemented methods now answer a check, up from nine. Every `svc.*`, `file.*`, `pkg.*`, `identity.*`, `fw.firewalld.*`, `fs.*` and `archive.*` method, `win.feature.install` and `remove`, `container.docker.run`, `stop` and `remove`, and the AWS `ec2` and `s3` methods read the device (or the API) and predict what a real run would change, without changing it; a prediction leaves out what only the device decides, such as a new instance's ID, rather than guessing it. `facts.gather`, `net.ssh.ping`, `net.ios.facts`, `net.ios.ping` and the four `net.catalyst.*` methods only read, so a check runs them for real. `net.ios.save` predicts the change a save always reports without saving. `exec.command` and `exec.shell` can be checked when a `creates` or `removes` guard is set, and `http.request` when its method is GET, HEAD, OPTIONS or TRACE; `check_mode: true` on any other call of theirs is refused by `pleiades validate`, naming why. A check whose inputs are missing when it runs (an archive's source, a bucket that still holds objects, a running container removed without `force`) reports that task as "could not check" rather than failing it, since an earlier task in the same run may be what provides them.

The nine methods that still cannot be checked say why: the "could not check" line, `pleiades validate`'s refusal of `check_mode`, and the method's reference page all give the method's own reason (the new `Manifest.NoCheckReason`) in place of "does not declare check support".
