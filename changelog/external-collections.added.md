Added external Collections: a Collection method can now be built as a separate program with the public `pkg/external` SDK and loaded from the directory `PLEIADES_COLLECTIONS_DIR` names, with no fork and no rebuild of The Pleiades. Each program is checked by ownership, permissions and SHA-256 before every run, and receives exactly the credential a built-in method would: the one bound to the template, or the device's own. Every run is confined with Linux's Landlock to the program's own directory, the system files it needs, the `known_hosts` file and a private temporary directory, plus any path granted with `PLEIADES_COLLECTIONS_READ_PATHS`, so a program cannot read the credential store, your SSH keys or The Pleiades's own environment. Loading is refused where Landlock is unavailable. A check from an external program is never run against a simulate-locked device; it is reported as not checked there. Nothing runs until its exact build is approved with the new `pleiades collection approve` command, which shows what the program provides first; `revoke` and `list` manage the approvals. An external method may not use a namespace any built-in method uses, nor `pleiades` or `ansible`. A program's description may not hold characters a terminal acts on, and its error messages and results are printed with them escaped.
