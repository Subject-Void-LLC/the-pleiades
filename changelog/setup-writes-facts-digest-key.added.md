`controller setup` now writes `PLEIADES_FACTS_DIGEST_KEY`: into `.env` for Compose, and into the Secret it writes for Helm, whose values file sets `secrets.existingSecretHasFactsDigestKey: true`. Running setup again over a `.env` written before it did adds only this key and leaves every other value as it was. Setup never replaces one, since a new key reads as every private file's digest changing at once. Since setup now owns the variable, a `PLEIADES_FACTS_DIGEST_KEY` line in `.env` is read by its strict parser, as the master key and JWT secret are: a quoted or `export` form makes `setup --check` (and so `make up`) refuse it by name. `make setup` and `make up` also refuse a shell that exports it, since docker compose would use the shell's value over `.env`'s. Back it up with the master key: a restore onto a new machine writes a new one unless you put the old one back.
