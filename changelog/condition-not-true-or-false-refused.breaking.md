A condition that is known not to be true or false (a string, a number, or an optional value such as `facts[?"os.codename"]` alone) is now refused when the runbook is built, by `pleiades validate` and by every run, in `when`, `when_or`, `when_cel`, `until`, `changed_when`, `failed_when` and an assertion's `that`, naming its type. That includes one in a task a run never reaches (an item after a false one in a `when` list, a rescue nothing triggered, a task `--tags` left out, a loop with no items), which used to pass with exit 0; add the test the condition meant, for example `.hasValue()`.
