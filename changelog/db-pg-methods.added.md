New `db.pg.query`, `db.pg.dump`, `db.pg.restore`, `db.pg.migrate`, `db.pg.grants` and `db.pg.rowcounts` methods work on a PostgreSQL database a device reaches, connecting from that device through its SSH session. `query` runs one prepared statement read-only (unless `write`) with statement and lock timeouts and returns CSV, failing past its row bound rather than cutting, and refuses a login a read-only transaction does not confine. `dump` writes a new archive with the device's `pg_dump` and can be rolled back; `restore` restores one in a single transaction into a database the task names, refusing a live database unless told why. `migrate` applies numbered SQL files in order, each in its own transaction and recorded, with an optional additive-only check by a SQL lexer, serializing concurrent runs by the version key rather than a lock. `grants` holds a role's privileges, memberships and ownership to a declared set, and `rowcounts` compares two databases table by table from one snapshot each.
