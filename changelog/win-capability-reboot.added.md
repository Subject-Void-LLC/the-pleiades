Three methods prepare a Windows host over WinRM. `win.capability.install` and `win.capability.remove` make a Windows capability (a feature on demand, such as `ServerCore.AppCompatibility~~~~0.0.1.0`) present or absent with DISM, reading its state first so a converged host reports no change, and each records the other as its undo. Windows Update refuses a WinRM logon, so the change runs DISM as SYSTEM in a one-shot scheduled task, or from a `source` of feature-on-demand media with Windows Update left alone; a capability left waiting for a restart reports `reboot_required`. `win.reboot` is `ansible.windows.win_reboot`: it restarts the host with `shutdown.exe` and waits until WinRM answers with a new boot time, within `reboot_timeout`.
