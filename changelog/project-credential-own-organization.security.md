A project may now bind only a credential its own organization owns. `POST /projects`, `PATCH /projects/{id}` and the web UI's project form refuse another organization's credential with a 400 on the `credential` field that says no such credential exists in the project's organization, and a sync refuses to use one: before, a project in one organization could bind another organization's source control credential, and a sync sent it to whatever host the project names. A project already bound to another organization's credential stays readable, but its syncs fail, saying the credential belongs to another organization, until it is bound to one of its own. The UI's credential chooser now names each credential's organization. This keeps a project and its credential in the same organization; it does not keep a caller to their own organization, since authorization is still by token scope across the deployment, so a caller holding `project:write` can still create a project in another organization and bind that organization's credential.
