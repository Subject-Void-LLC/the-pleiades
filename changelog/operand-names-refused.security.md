A package, unit or service name that begins with `-`, or holds `*`, `?`, `[` or `]`, is refused for every `pkg.*`, `pkg.apt.*`, `pkg.dnf.*`, `svc.*`, `svc.systemd.*` and `svc.windows.*` method, and so is such an `owner` or `group` on `file.copy`, `file.template`, `file.directory`, `file.permissions` and `file.touch`: by `pleiades validate` when it is written in the task, and before anything is sent when it is rendered from a variable or a registered result. Before, apt-get, dnf, systemctl and chown could read such a name as an option or as a pattern matching many packages or units (GNU `chown` took an owner of `--reference=/etc/shadow` as "give the file `/etc/shadow`'s owner and group"), and `pkg.apt.install` with a name ending in `-` removed the package; every name now also follows a `--` on the command line, and a `dpkg-query` or `rpm` that fails to answer fails the task instead of reading as "not installed". A `file.symlink` `src` that begins with `-` no longer reaches `ln` as an option (GNU `ln` read `-t/etc` as "make the link in `/etc`" and replaced the file of that name there, a file the method never checked), and every path, owner, group and link target a file method sends now follows a `--` or, for a relative path, a `./`.
