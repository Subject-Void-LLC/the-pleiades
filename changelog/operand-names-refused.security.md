A word a program would read as an option, as a pattern, or as its own syntax for something other than the one thing named is refused before anything is sent: package, unit, service, account and group names, file owners and groups, package versions (`version: "*"`, or an APT version ending in `-`, which removed the package), APT names naming a release or a version (`jq/bookworm`, `jq=1.6`) or ending in `-`, dnf groups, files and capabilities (`@core`, `/usr/bin/jq`, `perl(strict)`), and `fs.mount` and `fs.unmount` fields beginning with `-` (a mountpoint of `-a` ran `mount -a`) or holding a space, a line break or `\` (each wrote other fstab fields or lines); `pleiades validate` refuses one written in the task, the engine one rendered from a variable or a registered result, and `pleiades rollback` one in a journaled undo. A fresh `pkg.apt.install` or `pkg.dnf.install` (and an upgrade of an absent package) also refuses a name its package manager has no package of exactly that name for, such as a virtual package, `jq+` (which apt-get read as jq) or `vim` (which dnf installs as vim-enhanced), since the undo recorded under that name removed nothing.

Every operand now follows a `--` wherever the program takes one (apt-get, apt-cache, dpkg-query, rpm, systemctl, chown, chgrp, chmod, the shadow tools, ln, rm, mkdir, touch, mount and umount, and `rm -rf` of an `archive.*` source), and a relative path pkg/remotefile sends to cat, sha256sum, shasum or mktemp starting with a dash is sent as `./path`; dnf and musl's getent read `--` as a word, so for those the refusal alone keeps a name from their options. A `dpkg-query`, `rpm` or `findmnt` that fails to answer now fails the task instead of reading as "not installed" or "not mounted", `win.feature` names are held to the form DISM lists, and a `win.reboot` message beginning with `/` or `-` is refused.
