Added the controller's upgrade path. `controller migrate --plan [--json]` says what starting a build would do to a database, without changing it, and its exit code is its answer. `make up` runs it and takes a backup before any upgrade of a database that holds data. Migrations follow a written, tested compatibility rule: they expand the schema unless declared as contracts, so the previous build keeps serving during a rolling upgrade and a controller can be rolled back within that window. Every migration records the oldest build that can serve it, a controller refuses a database migrated past its window, and a running one stops when that happens. See "Upgrading and rolling back" in the production guide.
