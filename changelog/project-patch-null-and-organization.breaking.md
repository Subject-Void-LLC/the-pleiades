`PATCH /projects/{id}` refuses a null on any field with a 400 that names it; leave a field out to keep it, or send an empty value to clear it. A null used to be read as the field's empty value: it cleared `description`, `scm_url` (refused for a git project) and `scm_branch`, a null `scm_type` made the project git, a null `credential` unbound it, a null `name` was refused as a missing name, and a null `organization` was ignored. It also refuses an `organization` that differs from the stored one with a 400 naming the field, where it used to be accepted and ignored with a 200; sending the stored value is still accepted.
