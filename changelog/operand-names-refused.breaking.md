A wildcard in a package, unit or service name (`pkg.dnf.install` with `name: "kernel-devel-*"`) or a package version is now refused rather than passed to the package or service manager; name each package or unit on its own task, or loop over the names. A `pkg.apt.*` name naming a release or a version (`nginx/bookworm-backports`, `nginx=1.24`), ending in `-`, or that APT has no package of exactly (a virtual package such as `awk`), and a `pkg.dnf.*` name naming a group, a module, a file or a capability (`@development`, `/usr/bin/htop`, `perl(DBI)`, or `vim`, which dnf installs as vim-enhanced), are refused: give the version in `version` and name the package itself, which `apt-cache showpkg` or `dnf provides` tells. systemd's root units, `-.mount` and `-.slice`, are taken by their exact names; every other unit name beginning with `-` is refused.

The `owner` and `group` of `file.copy`, `file.template`, `file.directory`, `file.permissions` and `file.touch`, and the `name` and primary `group` of the `identity.user.*` and `identity.group.*` methods, are held to the same rule, so an account or group whose name holds `*`, `?`, `[` or `]`, which useradd and groupadd make on Debian 12 and Ubuntu 22.04 and 24.04, can no longer be named there. An `fs.mount` or `fs.unmount` mountpoint, source, type or options holding a space, a tab, a `\` or a control character, or beginning with `-` or `#`, is refused, so a mount whose fstab entry writes a space as `\040` cannot be managed by these methods. `win.feature` names hold only letters, digits, `.`, `_` and `-`, and a `win.reboot` `msg` cannot begin with `/` or `-`.

A rollback holds each recorded undo to the same rules, so an undo recorded before them with a value they now refuse is accepted only by `--leave`, which drops the whole step: a `file.permissions` undo whose earlier owner holds `[` loses its mode restore as well. On the Walk tier, a rollback planned by an older Controller and run by a newer Runner fails at the Runner when the newer rules refuse a recorded value, and is planned again.

`file.directory` now refuses an all-digit `owner` or `group`, as its documentation already said and as the other file methods do: name the account instead.
