A private key pasted into a client certificate field was stored and carried as the one public field of a credential, which run output does not mask by value. Any PEM block other than `CERTIFICATE` there is now refused, naming the field the key belongs in: by `add-credential --certificate`, by the credential file on save and on read, by `import-kubeconfig` and `POST /inventory/kubeconfig-imports` for a kubeconfig's `client-certificate-data`, and by the Controller's credential store and injection for a Kubernetes or cryptography credential's certificate input.
