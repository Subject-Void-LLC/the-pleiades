`file.remove`'s check now fails, naming the path and why, when the device's own permissions say the login may not remove it, since the real run would likely be refused; set `check_forbidden: warn` to get a warning instead. Where the device cannot say (a root login under a BusyBox shell, as on Alpine), the check warns rather than fails, so a rollback check of a recorded removal is not refused there; a real run ignores the setting, and any value but `refuse` or `warn` is refused.
