Every command sent to a device over SSH now reaches it through `/bin/sh`, whatever the account's login shell is, so file, service, package, rollback, check, onboarding and async work behaves the same on a host whose account logs in to bash, zsh, tcsh or fish; before, a tcsh or fish login broke much of it, sometimes reporting success having done nothing. An `ssh_exec` command runs under `sh` too, as Ansible's shell module runs its command, so one written with bash-only syntax for a bash login now needs `exec.shell` with `executable: /bin/bash`. A network device's CLI, and a device onboarding found no POSIX shell on, still get each command as written.
