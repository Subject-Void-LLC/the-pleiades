`PATCH /inventories/{id}` and `PATCH /announcements/{id}` are now partial updates: a field the body leaves out keeps its stored value, where it used to be blanked. An inventory PATCH that sent only its devices answered 500 for the name it blanked, and one that sent only the name erased the description. An announcement PATCH that did not send the title or the body answered 500, and one that sent both reset the level to info and erased the window, so a scheduled change freeze started showing at once and never ended. An empty description, an empty member list, and an empty `starts_at` or `ends_at` clear that field. The record as it would be saved is still checked whole: every inventory member again, and an announcement's window, so moving one bound past the stored other is refused. Two PATCHes of one inventory or one announcement now apply one after the other, each over what the other saved, so a PATCH that leaves out the members can no longer put back a member another PATCH removed; a member list a PATCH names still replaces the stored one whole, and there is still no version check. A blank inventory name and a blank announcement title or body answer 400 on create and on an update that changes them, where they answered 500 (and a name of spaces was stored by an update), and so does a NUL character in an inventory's name or description or an announcement's title or body, which answered 500 on PostgreSQL.
