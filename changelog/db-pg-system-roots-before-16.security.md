`db.pg.dump` and `db.pg.restore` refuse a `verify-full` connection with no pinned CA when the device's `pg_dump` or `pg_restore` is older than PostgreSQL 16, before contacting the server, and say to pin the CA (`ca_pem`): before 16, libpq reads `sslrootcert=system` as a file named `system` where it runs, so such a run failed on a clean device, and a file planted under that name in the login's home became the authority the server was verified against. The tools also run from the run's own private directory now, so a libpq older than its program reports finds no such file either.
