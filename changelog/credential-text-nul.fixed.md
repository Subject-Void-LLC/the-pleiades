Creating or updating a credential with a blank name is now refused with a 400 naming the field, where the API answered 500. A NUL character in a credential's `name`, `description` or `external` reference, in an input source binding's `metadata`, or anywhere in a credential type (its `name`, `description`, input schema or injector document), is refused with a 400 naming the field, or an error beside it in the web UI's forms, where SQLite stored it and PostgreSQL would fail the write with a 500. The rules are checked in the credential store, so the API and the web UI are held to them alike.
