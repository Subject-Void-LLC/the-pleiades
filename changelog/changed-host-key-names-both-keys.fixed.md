A refused SSH host key now says what was refused: the port, the key the host presented and each key known_hosts trusts for it with its file and line, and the `pleiades trust-host <device> --first-connect --replace` command that accepts a new key once its fingerprint is checked against the device, where before it said only `knownhosts: key mismatch`. The key stays refused, and `wait.connection` still stops at it on the first try that reaches the device.
