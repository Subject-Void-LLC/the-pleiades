Saving an inventory's edit form in the web UI no longer undoes a change someone else made after the form was opened. The form used to replace the whole inventory with what it showed, so saving a description fix after another operator or an API client had removed a device put the device back. Now the save applies only what the form changed: a device or group it deselected is removed and one it selected is added, while every other change made since stays. When the form and someone else both changed the name or the description, the save is refused beside that field, and the form must be opened again; submitting the refused form again is refused again. A device the chooser cannot list is kept, and a name stored past the form's length limit no longer blocks editing the description. A refused form in any view now shows every option that was selected in a multiple-choice control, where it used to show only the first, so saving it again no longer dropped the others.
