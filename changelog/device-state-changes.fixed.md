Fixed promoting a device. `PATCH /api/v1/inventory/devices/{name}` with a new `state` or `tags` answered 200 and stored nothing, so a device could not be moved out of quarantined or simulate-locked; each change is now stored and recorded as a revision in the device's history. A later `pleiades inventory sync` no longer puts a promoted device back to the state its source first gave it, and `inventory sync --read-only` now lists the devices needing review, with the reason each was quarantined, instead of only when nothing would change.
