Under `pleiades run --limit`, and in a `serial:` batch, a task whose `target:` (or a name in the runbook's `hosts:` list) names only devices the limit or the batch leaves out is now skipped, naming those devices and why, instead of failing with "matches no inventory host or tag". A name the inventory has no device or tag for still fails, limited or not. A rescue task the limit or the batch leaves out while its block is handling a failure is not skipped: it fails, naming the limit or the batch, so the failure stands and the run exits non-zero rather than reading as rescued. The journal records such a skip with the new skip kind `limit`, which an older build's strict journal reader refuses: on an older binary that run's journal does not read, and `pleiades journal list` and `pleiades rollback`, which read every run, stop at it.
