A kubeconfig import that refuses its cluster's server address no longer repeats the address in its error: an address carrying a password (`https://user:pass@host`) or a token in its query was quoted back in `pleiades import-kubeconfig`'s message and in `POST /inventory/kubeconfig-imports`' 422 response, and an address that did not parse was repeated by the URL parser's own error. Each refusal now names what is wrong without the address.
