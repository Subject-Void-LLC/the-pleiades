`PATCH /organizations/{id}`, `PATCH /teams/{id}`, `PATCH /contacts/{id}` and `PATCH /bindings/{id}` refuse a null on any field with a 400 that names it; leave a field out to keep it, or send an empty value to clear it. A null used to be read as the field's empty value: it cleared a text field that can be empty (an organization's description, classification, change window, freeze reason, cost centre, ticket key and CMDB id, a team's description, a contact's email, phone, URL and notes), a null `frozen` unfroze the organization, a null on `name`, a contact's `role` or a binding's `role` or `effect` was refused with a 400 that did not name it, a null on a team's `users` or a contact's `order` kept the stored value, and a null on a fixed field was ignored with a 200. They also refuse a value that differs from the stored one for a field no update can change, with a 400 naming the field, where it used to be accepted and ignored with a 200: a team's `organization`, a contact's `organization` and `team`, and a role binding's `team`, `scope_type` and `scope_id`; sending the stored value is still accepted.
