`PATCH /credentials/{id}` and `PATCH /credential-types/{id}` are now partial updates: a field the body leaves out keeps its stored value, where it used to be blanked. A credential PATCH that did not name `external` erased every external secret reference the credential held, so a rename saved cleanly and broke the next run that needed the secret, and one that did not name `name` answered 500; a credential type PATCH that did not name `name` or `kind` was refused for the one it blanked, and one naming both erased the input schema and the injector document. A credential's `inputs` still merges (an input left out is kept, `$encrypted$` keeps a stored secret and `""` clears an input), its `external`, when named, replaces the stored references whole, so an entry left out is removed and `{}` removes them all, and a type's `inputs` and `injectors`, when named, each replace the stored document whole; the record as it would be saved is still checked whole, and concurrent PATCHes are still last-writer-wins, with no version check.
