A refused web UI project form no longer shows back a source URL that may carry a credential. The form is redisplayed with what was submitted, so a create or an edit refused for a URL like `https://user:token@host/repo` put the password on the 422 page; the URL control now shows it redacted or withheld, as a stored URL is shown, with the error still beside it. A refusal for any other reason redisplays a clean URL as typed.
