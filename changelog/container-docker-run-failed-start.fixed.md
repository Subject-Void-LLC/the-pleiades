`container.docker.run` no longer leaves a container behind when docker creates it and then fails to start it (a host port already taken, for example): the failed run removes the container it left "created", and says so, so the next run creates and starts it instead of finding the name and reporting no change. A run's undo is now pinned to the id docker run itself printed, so it is kept, with a warning, even when the container cannot be read back afterwards.
