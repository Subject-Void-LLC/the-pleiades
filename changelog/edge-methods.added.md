New `edge.tunnel`, `edge.access` and `edge.dns` methods check what a Cloudflare account serves against what a runbook expects, on a `cloudflare_account` device whose API token is its own credential, held by reference, sent only to its API and never in output. `edge.tunnel` checks a tunnel's status and how many connectors are up; `edge.access` checks an Access application's audience, issuer, domain, session duration and policies, each policy by name as missing, changed or extra; `edge.dns` checks a name's record set, proxying and TTL, or that there is none. Each fails listing every difference, follows Cloudflare's pagination up to 50 pages, retries only rate limits and server errors, and only reads, so a check of it is the task itself. `pkg/cfapi` is the read-only client, and `pkg/cfapi/cfapitest` a server answering as Cloudflare's API documents, for tests.
