New `build.digests.check`, `build.digests.refresh` and `build.lock.verify` methods check what a build depends on, on the device that holds the project. `build.digests.check` lists every image reference in a Dockerfile, a Compose file or Kubernetes manifests not pinned by both tag and digest, and with `resolve` reports a pin its tag no longer names. `build.digests.refresh` moves each pin to the digest its tag names now, resolved through the device's own container engine (a multi-platform image's index digest), refuses a file edited meanwhile, keeps each file's mode, owner and group, and can be rolled back: before writing it keeps the references it replaces in a private undo record on the device, which the rollback replays. `pkg/remotefile` gains `ReadText` (a bounded read of a regular UTF-8 file) and `Replace` (a write that keeps a file's owner and group, in place when a new file could not be given them). `build.lock.verify` checks that an npm `package-lock.json` or a Cargo `Cargo.lock` covers its manifest, carries an integrity hash for every entry, and draws only from allowed sources.
