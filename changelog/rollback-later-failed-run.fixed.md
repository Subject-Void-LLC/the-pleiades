A rollback now refuses beneath a later run that had a task fail during its action on a device the rollback undoes on, in a method that is not read-only, since that task may have changed the device partway; name the run with `--despite-run` (or `despite_job` on the Controller) once the device is known to be as the earlier run left it. This refuses more often than before, including for an `until:` poll's failed tries and a failure `ignore_errors` let the run go past, and rolling that later run back does not clear it; the refusal's kind is `unknown_effect`, and `unknown_effects` names the failed methods, in `--json` and in the Controller's refusal, which now also gives each problem's `kind`.
