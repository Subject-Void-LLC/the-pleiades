A login a device refuses, an SSH host key `known_hosts` refuses or a WinRM certificate this side refuses no longer counts as the device being healthy: it never clears a run of failures to reach the device or closes an open circuit, so a device whose logins time out and are refused by turns (a failing TACACS+ or RADIUS server) now opens its circuit and stops being sent the credential, and when such a refusal answers the one call let through an open circuit, the next call is let through in its place. A task whose login is refused (over SSH, WinRM or Telnet) is no longer run again for its `until`, and a `loop` runs none of its items after one whose login was refused, on the CLI and on a Runner alike: before, `retries: 5` sent the refused password six times and a loop sent it once per item, enough to lock an account from one task. An SSH dial its caller canceled (a stopped run, an interrupted task) no longer counts toward the device's circuit, as a canceled WinRM call already did not, so stopping a run can no longer open a healthy device's circuit for every other task. A detached (async) command whose connection dropped and whose reconnect was refused is no longer dialed a second time, with the same credential, to stop it.
