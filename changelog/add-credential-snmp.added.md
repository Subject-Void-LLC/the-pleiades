`pleiades add-credential` stores a device's SNMP credential apart from its login: an SNMPv1/v2c community (`--snmp-community`, `--snmp-community-stdin`) or an SNMPv3 user (`--snmp-user`, `--snmp-auth`, `--snmp-priv`, its passphrases prompted for or read with `--snmp-passphrase-stdin`), with every USM protocol accepted and AES-192/256 named apart for the Blumenthal and Reeder key extensions. Saving SNMP keeps the login and saving a login keeps the SNMP fields, `list-credentials` names the `snmp_community`, `snmp_v3_auth` and `snmp_v3_priv` kinds, and a community shorter than 8 characters is stored only with `--allow-short-community`, after which every run that uses it warns that it is masked by shape only. No method speaks SNMP yet. A device's own SNMP fields never leave the Controller on a dispatch, whatever the job's kind: until a release with an SNMP client adds them back for the methods that declare they need them, only a template's bound `pleiades_snmp` credential reaches a Runner.
