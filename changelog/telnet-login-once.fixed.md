Fixed a Telnet login sending the stored password again when the device asked for it again: IOS re-prompts a wrong line password with no refusal text, and each resend counted another failure against the device's lockout. A password, or a name, asked for again is now the login refused. A Telnet read is also bounded as a whole (`MaxReadDuration`, five minutes by default) and by the bytes it reads, negotiation included, so a device that only negotiates or sends a byte at a time no longer holds a run for as long as its context allows.
