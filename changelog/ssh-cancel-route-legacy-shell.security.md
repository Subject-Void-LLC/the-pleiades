SSH commands and Collection connections are held to what they were asked to do. A command whose task timed out or was cancelled now always fails with the cancellation; it used to come back from OpenSSH as a finished command (its partial output with no error, or exit 143), and a cancelled or failed write of standard input could be reported as a success. A task cancelled before it starts sends nothing. On `pleiades run` and `pleiades adhoc`, a Collection method's own connection to a device behind a bastion (`route`), and `net.ssh.ping`'s, now goes through the bastion, as `ssh_exec` does, instead of straight to the device's address; a Runner, an external Collection and onboarding's SSH probe still dial the address directly. A device onboarded before the shell-agnostic change whose login shell was fish or tcsh had `shell: not posix` recorded, which later releases read as "no POSIX sh" and sent its commands raw to fish, where a quoted value could run as code; that value is now ignored, and onboarding records `shell: no posix sh` for a device that truly has no sh. A device onboarded before that change that has no POSIX sh (a Windows OpenSSH server, or a router or appliance added as `generic_ssh`) fails at `/bin/sh` until it is onboarded again, and a Runner older than this release reads the new value as POSIX and fails the same way on such a device until it is upgraded.
