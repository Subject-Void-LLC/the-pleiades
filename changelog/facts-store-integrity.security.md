Stored facts are harder to leak, forge or wedge. A fact whose value holds a field named like a secret at any depth (such as `{"db": {"password": ...}}`) is no longer stored, on the command line or on the Controller, and the run's log names the field, never the value. `pleiades facts <host> --verify` and the Controller's chain check now count a stored value with no chain as a break wherever it stands, rather than passing such values at the start of a history as older rows, and their `unchained` count is gone. The Controller now drops a facts batch, run journal batch or job result whose job or device ID is malformed, or which its database refuses as data, instead of retrying it until the message's delivery budget runs out, and a NUL byte in a job result's reason (which can come from a device's own output) no longer costs the device its recorded result. The command line's fact store now writes its files so that a crash during a write cannot leave a state file that refuses the device's facts afterward, and it reads an empty state file left by an older build as no state. A result stored late no longer makes the next run record a change that did not happen. These affect only builds after 0.3.0.
