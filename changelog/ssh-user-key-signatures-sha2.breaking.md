A device that logs in with a stored RSA or DSA key, and whose SSH server advertises no SHA-2 signature for that key, is now refused, naming `ssh_allow_legacy_user_key_signatures`; set it only for a device known not to take SHA-2, since a removed advertisement looks the same. A credential that also holds a password logs in with it instead, with a warning, so a stale stored password now costs one failed login per connection toward an account lockout (`pam_faillock`, a directory policy). A project synced over SSH from a git server that advertises no SHA-2 signature for its RSA key now fails, with no property to allow it; the failure says to "log in with an ed25519 or ECDSA key, or have the server take rsa-sha2-256". Upgrade Controllers before Runners: a Controller that predates the property does not pass it to a Runner, which then refuses the key even on a record that sets it.
