`container.start`, `container.stop` and `container.restart` now return only once Docker's own container list shows the change, since Docker Engine before 28.3.0 could list the old state for a moment after answering, and a later task (such as a `container.prune` check) could miss it. If the read after the change fails, the task warns and still succeeds with its undo, and stopping a container that Docker removes when it stops (`--rm`) records no undo, since none could run.
