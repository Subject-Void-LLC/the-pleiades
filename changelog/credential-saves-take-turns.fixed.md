Commands that write the project's credential file at the same time no longer lose each other's entries: every command that writes `.pleiades/credentials.yaml` now holds an operating system lock on `.pleiades/credentials.lock` across its read and its write, and one that waits 30 seconds for it stops with an error naming the lock file (a run clearing an unbound credential's mark waits two seconds and then leaves the mark for the next run). The lock uses `flock` on Linux, macOS and FreeBSD and `LockFileEx` on Windows and has run on Linux only so far; a `pleiades` older than this change takes no lock, and a network filesystem may not keep one between machines.
