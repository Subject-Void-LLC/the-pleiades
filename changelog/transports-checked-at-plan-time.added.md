`pleiades validate` now refuses a task whose device cannot be reached over any transport its method uses, naming the transports on both sides: for example `exec.command`, which speaks SSH, against a Windows server reached only over WinRM. The same check runs again before the method runs, on the CLI and on a Runner. A method may list only the transports the platform knows (`ssh`, `winrm`, `netconf`, `https`, `docker`), and the capability reference lists which capability reaches each. A runbook that validated before can now be refused if one of its tasks targets a device its method could never have reached; such a task already failed when it ran.
