A runbook with `lock_acquisition: all_at_plan_time` on a `rescue:` task no longer builds, so `validate` and `run` refuse it before any task runs, where `validate` used to pass it and the run failed only when it reached the rescue; a rescue in a block that runs as one unit (some task of the block has a `target` of its own) may still take the lock, and a tag selection that leaves that task out is refused by `validate` and `run`. The refusal of that lock on a task that reads variables differing by device, or whose condition reads stored `facts`, now names that cause instead of saying the task "reads device", in the same words from `validate` and the run, and for `facts` it is reported by the `template` rule where it was the `facts` rule's.
