`pleiades add-credential <device> --username <user> --generate` stores a new random ed25519 key and a new random 24-character password in the vault, and prints only the key's public half; `--replace` is needed to discard a credential the device already has. A method that creates a machine can seed it with a device's stored login (`collection.Manifest.SeedsLogin`): the engine hands it only the user name, the public key and a freshly salted SHA-512 crypt hash of the password (`pkg/shacrypt`), never the key or the password. Only the `pleiades` CLI resolves a seeded login so far; the Controller and Runner refuse such a method, and an external Collection may not declare one.
