A stored RSA key no longer signs an SSH login with `ssh-rsa` (SHA-1), which the SSH library chose whenever a server did not advertise SHA-2, including a server whose advertisement a machine in the middle removed; it signs with `rsa-sha2-512` or `rsa-sha2-256`, and a DSA key does not sign at all. A device opts back in only through `ssh_allow_legacy_user_key_signatures: true` on its own record, which no other legacy property implies and which is warned about on every run and onboarding that has it; a project synced over SSH has no such opt-in. A credential holding a key and a password whose key is refused this way logs in with the password and warns that the key was not used, and a route's bastion now reports its legacy SSH warnings on the task whatever rides the route (SSH, Telnet, a serial console, or a method's own connection). A key handed to `ansible-playbook`, or used by an external Collection outside `sdk.Connect`, is not covered.
