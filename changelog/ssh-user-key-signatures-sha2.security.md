A stored RSA key no longer signs an SSH login with `ssh-rsa` (SHA-1), which the SSH library chose whenever a server did not advertise SHA-2, including a server whose advertisement a machine in the middle deleted; it signs with `rsa-sha2-512` or `rsa-sha2-256`, and a DSA key does not sign at all, unless the device's record sets `ssh_allow_legacy_user_key_signatures: true`, which no other legacy property implies and which is warned about on every run and onboarding that has it. A credential holding a key and a password whose key a server takes only with SHA-1 logs in with the password and warns that the key was not used, and a route's bastion now reports its legacy SSH warnings on the connection it carries.
