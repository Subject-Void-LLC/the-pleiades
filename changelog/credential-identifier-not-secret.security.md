A refusal built from a credential's input values quoted them, though a custom credential type may mark any input secret: refusing to bind two vault credentials, or two database connections, to one job template (`PUT /templates/{id}/credentials`) quoted the vault identifier or connection name they shared, injecting a database connection quoted its `port`, `host`, `sslmode`, `name` or a `live` database, injecting a Kubernetes credential quoted its `host`, and a HashiCorp Vault source credential's refusal quoted its `url` scheme or `api_version`. The value then reached an API response or a job's failure reason, where nothing masks it. Every such refusal now names the credential, the input and the rule it breaks, never the value, which also covers a type stored before the rule below. A type marking a vault type's `vault_id` or a database type's `name` secret is now refused when it is saved.
