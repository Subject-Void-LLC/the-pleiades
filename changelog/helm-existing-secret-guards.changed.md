With `secrets.existingSecret` and the in-chart database, the chart now builds the database connection string from the Secret's `POSTGRES_PASSWORD` rather than reading a `DB_DSN` key, so an operator's Secret no longer repeats a name derived from the release. Two new values, `secrets.existingSecretChecksum` and `postgresql.auth.existingSecretFingerprint`, restore what such a Secret used to switch off: restarting the pods when the Secret changes, and refusing a reinstall onto a database volume created with a different password. `controller setup --target helm` writes both.
